# ناظرِ خودکارِ سامانه

یک **Routine** (زمان‌بندِ Claude Code) که هفته‌ای دو بار کلِ سامانه را بازرسی
می‌کند — **بدبینانه** و **اجرایی** — و خودش اصلاح، کامیت و پوش می‌کند.

## شناسهٔ Routine

| مورد | مقدار |
|---|---|
| نام | ناظرِ خودکارِ سامانه (Automated Supervisor) |
| شناسه | `trig_016NiM3KX8iZi4bERnkv2Bwr` |
| زمان‌بندی | `0 3 * * 2,6` (UTC) — سه‌شنبه و شنبه، ساعتِ ۷ صبحِ دبی |
| مقصد | **همین گفت‌وگو** — خلاصهٔ هر اجرا این‌جا نوشته می‌شود |

## چطور دستورش را عوض کنم؟

**`PROMPT.md` را ویرایش کن، نه پرامپتِ خودِ Routine را.** پرامپتِ Routine عمداً
فقط یک اشاره به همین فایل است، تا تاریخچهٔ دستور در گیت بماند.

روالِ تغییر:
1. نسخهٔ فعلی را بایگانی کن:
   `cp docs/supervisor/PROMPT.md docs/supervisor/archive/PROMPT-v{N}-{YYYY-MM-DD}.md`
2. `PROMPT.md` را ویرایش کن و `version` را در frontmatter یک واحد جلو ببر و
   `supersedes` را پر کن.
3. کامیت و پوش. اجرای بعدیِ ناظر خودکار نسخهٔ جدید را می‌خواند.

## فایل‌ها

| فایل | نقش |
|---|---|
| `PROMPT.md` | دستورِ کاملِ ناظر — تنها مرجعِ رفتارش |
| `archive/` | نسخه‌های قبلیِ دستور |
| `HANDBOOK.md` | جزوه: نقشهٔ سامانه، نمودارها، روندِ پیشرفت (خودکار) |
| `INVENTORY.md` | فهرستِ خودکارِ صفحه‌ها/دکمه‌ها/مسیرها (خودکار) |
| `RUNLOG.md` | گزارشِ هر اجرا، جدیدترین در انتها |
| `OPEN_ITEMS.md` | کارهای بازِ انتقالی بینِ اجراها |
| `runs.jsonl` | سنجه‌های هر اجرا — منبعِ نمودارها |
| `last_runtime.json` / `last_db_audit.json` | خروجیِ خامِ آخرین اجرا |

## اسکریپت‌ها

```bash
python3 scripts/supervisor/inventory.py        # فهرستِ سطحِ سامانه از روی کد
python3 scripts/supervisor/runtime_check.py    # بالا آوردنِ برنامه + کلیکِ واقعی روی هر دکمه
cd backend && python3 ../scripts/supervisor/db_audit.py   # بازرسیِ بدبینانهٔ داده
python3 scripts/supervisor/update_handbook.py  # بازتولیدِ جزوه و نمودارها
bash scripts/supervisor/run_all.sh             # هر چهارتا، پشتِ سرِ هم
```

## محدودیتِ شناخته‌شده — دسترسی به production

محیطِ اجرای Claude Code به میزبانِ production **دسترسی شبکه ندارد** (سیاستِ
Network access، پاسخِ ۴۰۳ به CONNECT). بنابراین ناظر **نسخهٔ محلی** را اجرا و
بازرسی می‌کند و دادهٔ واقعی را نمی‌بیند. هر گزارش صریحاً می‌گوید کدام دیتابیس
بازرسی شده است.

برای بازرسیِ دادهٔ واقعی یکی از این دو لازم است:
- میزبانِ production در تنظیماتِ **Network access** محیط مجاز شود؛ یا
- یک `SUPERVISOR_DATABASE_URL`ِ **فقط-خواندنی** به‌عنوان secret محیط اضافه شود.
