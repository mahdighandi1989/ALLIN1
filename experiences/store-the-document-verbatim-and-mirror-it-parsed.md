# سندِ اصلی را عیناً نگه دار، عددش را جداگانه آینه کن

## 🎯 چالش / Challenge

باید سندی رسمی را به یک فرمِ نرم‌افزاری تبدیل می‌کردیم که هم **عیناً مثل کاغذ
چاپ شود** و هم دیتابیسش **قابلِ کوئری و جمع‌زدن** باشد. دو فشارِ مخالف:

* اگر مبلغ را `Numeric` بگیری، قالب‌بندیِ اصلی می‌میرد. در سندهای بانکیِ فارسی
  `-/312,240` یعنی «عددِ رُند»، و `95/22.645` شکلِ استانداردِ نوشتنِ مبلغ است.
  چاپِ `312240.00` به‌جای آن‌ها یعنی سندی که گیرنده پس می‌فرستد.
* اگر متن بگیری، دفترِ گزارش‌ها هیچ‌وقت نمی‌تواند بگوید «جمعِ مطالبات چقدر است».

و یک تلهٔ سوم که تا وسطِ کار دیده نمی‌شود: **استخراجِ متن از صفحهٔ راست‌به‌چپ،
عددها را وارونه تحویل می‌دهد.** `22.645/95` روی کاغذ، از استخراج‌کننده
`95/22.645` بیرون می‌آید — دو رقمِ *قبلِ* اسلش اعشار است. هیچ `parseFloat` و هیچ
locale‌ای این را درست نمی‌خواند؛ بدترین حالت این است که چیزی برمی‌گرداند:
`65/ 113,004` به‌سادگی می‌شود شصت‌وپنج میلیون به‌جای صد‌وسیزده هزار.

## 💡 راه‌حل / Solution

> **متنِ سند را عیناً ذخیره کن، و کنارش یک ستونِ عددیِ *آینه* بگذار که فقط برای
> جمع‌زدن و مرتب‌سازی است. هیچ‌کدام منبعِ دیگری را بازنویسی نمی‌کند.**

1. ستونِ متنی = آنچه چاپ می‌شود. هرگز نرمال‌سازی نکن.
2. ستونِ `*_num` = آنچه کوئری می‌شود. از متن مشتق می‌شود، و **در نبودِ فهم NULL
   است، نه صفر**.
3. تبدیل‌کننده را روی **مبالغِ واقعیِ همان سند** بیازما، نه روی مثال‌های ساختگی.
   یک نمونهٔ پرشده که کاربر داده، ارزشش از ۵۰ تستِ تخیلی بیشتر است.

## 🧪 نمونه کد (Anonymized)

```python
amount      = Column(String(60))      # verbatim — this is what prints
amount_num  = Column(Numeric(18, 2))  # parsed mirror — this is what sums
# NO default=0 on the mirror. See the pitfall below.

FRACTION_FIRST = re.compile(r"^(\d{1,2})\s*/\s*([\d.,\s]+)$")

def parse_amount(raw):
    """Returns None — not 0 — when the text is not a number."""
    if raw is None: return None
    s = normalize_digits(str(raw))          # Persian/Arabic-Indic → ASCII
    s = strip_currency_words_and_markers(s) # «درهم», «-/», NBSP, ZWNJ
    if not any(c.isdigit() for c in s): return None
    m = FRACTION_FIRST.match(s)
    if m:                                    # RTL extraction: decimals came first
        whole = m.group(2).replace(",", "").replace(".", "").replace(" ", "")
        return Decimal(f"{whole}.{m.group(1)}")
    return Decimal(drop_thousands_separators(s))
```

## ⚠️ نکات حیاتی / Pitfalls

- **`default=0` روی ستونِ آینه، فاجعه است.** defaultِ ستون هنگام INSERT روی
  `NULL` شلیک می‌کند؛ پس «این مبلغ خوانده نشد» بی‌صدا می‌شود «این مبلغ صفر است».
  تست بنویس: «مقدارِ ناخوانا باید NULL بماند» — این تست ما را گرفت.
- **تبدیل‌کننده را در یک هارنسِ جدا «تأیید» نکن.** تابع را بیرونِ ماژول اجرا
  کردیم و ۳۵/۳۵ سبز شد؛ در خودِ برنامه `NameError` داد، چون هارنس `re` را به
  namespace تزریق کرده بود و ماژول importش نکرده بود. **هارنسی که کمبودهای
  ماژول را جبران می‌کند، هیچ چیزی را اثبات نمی‌کند.** همان تست را از داخلِ
  مسیرِ واقعی اجرا کن.
- **متنِ غیرعدد باید NULL بدهد، نه استثنا و نه صفر.** سلولِ «محاسبه سود متوقف
  گردیده» یک مقدارِ معتبرِ سند است.
- **جهتِ صفحه بخشی از قرارداد داده است.** هر جا متن از PDF/تصویرِ RTL می‌آید،
  فرض کن ترتیبِ اجزای عدد ممکن است جابه‌جا باشد و **نمونهٔ واقعی** را نگاه کن.
- **جداکنندهٔ هزارگان و اعشار محلی‌اند و گاهی در یک سند هر دو نقش را دارند**
  (`.` هم هزارگان دیده شد هم اعشار). قاعده را از خودِ سند دربیاور، از استاندارد نه.

## ⚠️ و یک تلهٔ بزرگ‌تر: سندِ اصلی را **ببین**، خلاصه‌اش را نخوان

همین کار یک اشتباهِ جدی‌ترِ هم‌خانواده داشت. برای بازساختنِ ظاهرِ یک فرمِ رسمی،
**استخراجِ متنِ** PDF را خواندم و هرگز خودِ PDF را باز نکردم. متن همهٔ کلمات را
داشت، پس به نظر کافی می‌آمد. نبود:

* استخراجِ متن **ترتیبِ بصری را نگه نمی‌دارد** — سربرگ و پانویس و شمارهٔ صفحه
  وسطِ متن ظاهر می‌شوند، و معلوم نیست کدام بالای صفحه بوده کدام پایین.
* **جدول از فهرست قابل‌تشخیص نیست.** چهار بخشِ سند جدولِ کادردار بودند؛ در متن
  شبیهِ «برچسب: مقدار» دیده می‌شدند و من همان‌طور ساختمشان.
* رنگ، قاب، پهنای ستون، سطرهای خالی، و این‌که سرستون‌ها سفیدند یا خاکستری —
  هیچ‌کدام در متن نیست.

نتیجه سندی شد که مالک درباره‌اش گفت «زمین تا آسمان فرق دارد». رندرکردنِ PDF
(`pymupdf`) و نگاه‌کردن به پنج صفحه، در چند دقیقه همهٔ این‌ها را نشان داد.

> **قاعده:** وقتی خروجی قرار است **شبیهِ** چیزی باشد، آن چیز را با چشم ببین.
> استخراجِ متن برای *محتوا* است، نه برای *ظاهر*؛ و اگر خواسته «دقیقاً همین شکل»
> است، خواسته دربارهٔ ظاهر است.

نکتهٔ فنیِ مرتبط: **نشان‌ها را از image streamِ خام بیرون نکش.** کانالِ رنگ بدونِ
soft mask می‌آید و لوگو جعبهٔ تیره چاپ می‌شود. همان ناحیه از صفحه را با `clip` در
dpi بالا **رندر** کن تا عیناً همان چیزی را بگیری که سند می‌کشد.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. هر فیلدی که **هم چاپ می‌شود هم محاسبه**: دو ستون، نه یکی.
2. ستونِ مشتق هیچ‌وقت `default` نگیرد؛ «نامعلوم» باید نامعلوم بماند.
3. مجموعهٔ آزمونِ تبدیل‌کننده را از یک **سندِ واقعیِ پرشده** بساز، و موارد
   «این عدد نیست» را هم بگذار.
4. تبدیل‌کننده را از همان مسیری صدا بزن که برنامه صدا می‌زند.
5. اگر منبع RTL است، قبل از نوشتنِ regex چند مقدارِ استخراج‌شده را با چشم با
   کاغذ مقایسه کن.
