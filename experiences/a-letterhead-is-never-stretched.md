# سربرگ را نکش، و کاغذ را از روی داده انتخاب کن

## 🎯 چالش / Challenge

یک سند رسمی (نامه/گزارش) سربرگ دارد: نشان، نامِ سازمان، و نوارِ آدرس. جعبه‌های
چیدمان تصویر را با `width:100%;height:100%` پر می‌کردند.

تا وقتی **یک** سربرگ وجود دارد این بی‌ضرر است — تصویرِ اول اتفاقاً نسبتِ جعبه را
داشت (۱٫۰۳۸ در برابرِ ۱٫۰۳۳). بعد شعبهٔ دوم آمد که نشان و نامش را **کنارِ هم**
چاپ می‌کند (۲٫۵۵:۱) و در همان جعبه به **۴۰٪ عرضِ خودش** فشرده شد. مالک گفت
«اشتباه است» و حق داشت: سربرگِ فشرده‌شده یعنی سربرگِ غلط، روی سندی که به دادگاه
می‌رود.

## 💡 راه‌حل / Solution

**۱) هرگز نکش.** `object-fit: contain` + لنگری که با کاغذِ واقعی بخواند:

```tsx
// نشان چپ‌بالا، نامِ سازمان راست‌بالا (RTL)، نوارِ آدرس وسط‌پایین
<img style={{ width:'100%', height:'100%', objectFit:'contain', objectPosition:'left top' }} />
```

**۲) تصویری که شکلش فرق دارد، جعبهٔ خودش را لازم دارد.** `contain` تضمین می‌کند
هیچ‌چیز بدشکل نشود، ولی تصویرِ خیلی پهن در جعبهٔ مربع، **درست ولی ریز** می‌شود.
اندازهٔ واقعی را از خودِ کاغذِ آن سازمان اندازه بگیر (PDF را رندر کن و جعبهٔ مرکب
را بسنج) و به‌عنوانِ override فقط برای همان یکی بگذار:

```ts
logoBox: { x: 14, y: 3, w: 47, h: 18 }   // میلی‌متر، از روی قالبِ خودِ مالک
```

و **فقط وقتی اعمالش کن که کاربر چیدمان را دستی جابه‌جا نکرده باشد** — جعبه‌ای که
کاربر کشیده یک تصمیم است.

**۳) دامنهٔ تغییر را محدود کن.** سربرگِ قدیمی که ماه‌هاست بی‌شکایت چاپ می‌شود را
عوض نکن؛ `contain` را فقط به نوعِ سندِ تازه بده. یک اصلاحِ درست هم اگر بی‌درخواست
ظاهرِ چیزی را عوض کند، یک باگِ تازه است.

**۴) رجیستری، نه شاخهٔ `if`.** یک فهرست که همه‌چیزِ هر سازمان/شعبه را دارد:

```ts
{ code, sender, faName, enName, aliases, logo, name, footer, logoBox? }
```

سربرگ، امضاکننده و لیستِ کشویی همه از همین می‌خوانند ⇒ **افزودنِ بعدی یک ردیف است**.

**۵) انتخاب از روی داده، با «نمی‌دانم»ِ صریح.** مقدارِ ذخیره‌شده معمولاً متنِ آزاد
است (کد، نامِ انگلیسی، «AL MAKTOUM - 2624»، یا خالی). تطبیق سخاوتمند باشد ولی
**حدس نزند**:

```ts
if (s === b.code) return b                       // کدِ خالص
if (digitsIn(s).includes(b.code)) return b       // کد داخلِ متن
if (b.aliases.some(a => a.length > 2 && s.includes(a))) return b
return null                                      // ← «نمی‌دانم»، نه «نزدیک‌ترین»
```

`null` یعنی کاغذِ پیش‌فرض. سازمانی که کاغذش را نداریم هم `null` می‌گیرد — چاپِ
تلفنِ یک شعبه روی نامهٔ شعبهٔ دیگر از پیش‌فرض بدتر است.

**۶) املاهای هم‌معنی را جدا بنویس.** «ك» عربی و «ک» فارسی **دو نویسهٔ متفاوت‌اند**
و دادهٔ ایمپورت‌شده هر دو را دارد؛ یکی تطبیق‌شدن و دیگری نه، یک خرابیِ
حساب‌به‌حساب و بی‌صداست.

**۷) انتخاب را روی صفحه نشان بده.** یک نشانِ کوچک «سربرگ: شعبهٔ …» — وگرنه کاربر
نمی‌فهمد اصلاً عوض شده یا نه و «چرا کار نکرد؟» جوابِ دیدنی ندارد.

## ⚠️ نکات حیاتی / Pitfalls

- **جفت‌شدنِ هدر و فوتر را فرض نگیر.** هر فوتر تلفن/فاکسِ خودش را دارد؛ اگر منبع
  فقط ترتیبِ فرستادن است، همان را به‌صراحت اعلام کن و جایی بگذار که عوض‌کردنش
  یک خط باشد. یک تست یکتابودنِ فوترها را ببندد.
- **`contain` مرکز می‌چیند**؛ بدونِ `objectPosition` نشان از لبهٔ کاغذ کنده می‌شود.
- **صفحهٔ دوم را یادت نرود.** هدرِ تکرارشونده معمولاً کدِ جداگانه‌ای دارد؛ اگر
  لنگر را فقط به صفحهٔ اول بدهی، صفحهٔ ۲ سربرگی به شکلِ دیگر چاپ می‌کند.
- **اندازهٔ کاغذِ منبع را چک کن** — قالبِ مالک ممکن است Letter باشد و برنامه A4.
- **به خروجی نگاه کن.** تست سبز نسبتِ تصویر را نمی‌بیند؛ سه سربرگ را روی ورقهٔ
  واقعی رندر کن و قبل/بعد را کنارِ هم بگذار.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. هر تصویرِ برندی که در جعبهٔ ثابت می‌نشیند را `contain` کن، با لنگرِ درست.
2. نسبتِ هر تصویر را با نسبتِ جعبه بسنج؛ اختلافِ زیاد ⇒ جعبهٔ اختصاصی.
3. همه‌چیزِ هر سازمان را در یک رجیستری بگذار تا افزودنِ بعدی یک ردیف باشد.
4. انتخاب را از دادهٔ واقعی بگیر و «نمی‌دانم» را صریح برگردان.
5. انتخابِ جاری را روی صفحه نشان بده.
6. خروجی را در مرورگر ببین، نه فقط تست.
