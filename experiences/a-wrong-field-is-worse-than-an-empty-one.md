# فیلدِ غلط از فیلدِ خالی بدتر است

## 🎯 چالش / Challenge

عاملِ خودکار خواستهٔ «**اینجا** این را بگذار» را گرفت و آن را «یک جای نزدیک»
گذاشت. مالک گفت «سلیقه رفتی». تشخیصِ اول: ضعفِ درکِ مدل.

**غلط بود.** وقتی دادهٔ تحویلی را نگاه کردم، فیلدی که می‌گوید «کاربر دورِ چه چیزی
کادر کشید» این بود:

```
covered_text: "/* English serif for LATIN LETTERS ONLY — Persian letters, digits …"
```

یعنی **یک کامنتِ CSS**. دو علتِ روی‌هم‌افتاده:

1. `textContent` محتویاتِ `<style>` و `<script>` را هم می‌آورد. صفحه‌ای که CSSاش
   را در یک `<style>` نگه می‌دارد، «متنِ دیدنی»‌اش استایل‌شیت می‌شود.
2. توصیف از `section ?? surface ?? innermost` گرفته می‌شد؛ صفحه‌ای که
   `data-report-section` ندارد (اکثرشان) ⇒ **متنِ کلِ صفحه**.

عامل با چنین ورودی **ناچار** سلیقه‌ای تصمیم می‌گیرد. فیلدِ خالی او را وادار به
پرسیدن می‌کرد؛ فیلدِ غلط به او اطمینانِ کاذب داد.

## 💡 راه‌حل / Solution

**۱) «متنِ دیدنی» را واقعاً دیدنی کن.**

```ts
const UNSEEN = new Set(['STYLE','SCRIPT','NOSCRIPT','TEMPLATE','SVG','HEAD','TITLE'])
// هم در شاخهٔ درختی، هم در شاخهٔ تک‌فرزند — باگ دقیقاً در دومی بود،
// جایی که کد یک‌راست سراغِ textContent می‌رفت
```

**۲) توصیف را از **نقطه** بگیر، نه از کلِ ظرف.** از خودِ عنصر شروع کن و فقط تا
اولین چیزِ خوانا بالا برو، و از مرزِ بخش/سطح فراتر نرو:

```ts
function nearestTelling(el, stop) {
  for (let cur = el, i = 0; cur && i < 6; i++, cur = cur.parentElement) {
    if (visibleText(cur, 1).length >= 8) return cur   // «۲۷۶» توصیف نیست
    if (cur === stop) break
  }
}
```

**۳) گاردی بگذار که **تصمیم** را مجبور به نوشته‌شدن کند.** گاردِ قبلی فقط «عکس»
می‌خواست، و عکسِ جای غلط هم از آن رد می‌شد. گاردِ مفید:

> اگر درخواست **هم** کادرِ گره‌خورده دارد **و هم** متنش «اینجا/این قسمت» می‌گوید،
> بستنش با «انجام شد» نیاز به یک جملهٔ صریح دارد: «کجا گذاشتمش».

ابزار نمی‌تواند بفهمد جا درست است — ولی می‌تواند مجبور کند تصمیم **گرفته و
نوشته** شود، و جمله را جلوی چشمِ کاربر بگذارد تا در یک نگاه غلط‌بودنش را ببیند.

**گارد را باریک نگه دار**، وگرنه تئاتر می‌شود: بدونِ کادر فعال نشود («اینجا»ی
بی‌کادر قابلِ اجرای دقیق نیست)، با درخواستِ غیرمکانی فعال نشود، و **حرفِ خودِ
عامل نباید آن را روشن یا خاموش کند**.

**۴) مختصات را با جهتِ درست برچسب بزن.** `rel.x` از **لبهٔ چپ** شمرده می‌شود؛
RTL بودنِ صفحه این را عوض نمی‌کند. من خودم «از راست» نوشتم و برای کادرِ نزدیکِ
وسط پنهان ماند — برای کادرِ کنارِ لبه، جا را **آینه** می‌کرد. معادلِ پیکسلی را هم
کنارش بنویس تا ابهام صفر شود.

## 🎯 چالشِ دوم (همان خانواده) — «جای دقیق داخلِ یک عنصرِ بزرگ»

کاربر دورِ **جدولِ بندِ ۳** کادر کشید؛ پیش‌نمایش گفت متنِ **بندِ ۱**. کد این بود:

```js
const inBox = stack.map((el) => el.closest('[data-lbox]')).find(Boolean)
const covered = (inBox?.textContent || '').slice(0, 400)
```

از مرکزِ کادر **بالا می‌رفت** تا ظرفِ نام‌دار. ولی کلِ متنِ فرم **یک** ظرف است،
پس هر کادری روی بدنه همان ظرف را می‌گرفت و `textContent`اش از اولین بند شروع
می‌شد. نتیجه: هر کادر، همیشه، همان پاراگراف — با اطمینان و غلط.

**قاعده:** وقتی ناحیهٔ موردِ نظر **داخلِ** یک عنصرِ بزرگ است، جای دقیق از اجداد
درنمی‌آید؛ از **هندسه** درمی‌آید.

```ts
// خطوطی که مستطیلِ خودشان داخلِ کادر است — نه ظرفی که کادر داخلش است
const w = doc.createTreeWalker(root, NodeFilter.SHOW_TEXT)
while ((n = w.nextNode())) {
  const r = doc.createRange(); r.selectNodeContents(n)
  if ([...r.getClientRects()].some((c) => overlap(box, c) / area(c) >= 0.4)) keep(n)
}
```

- **سهم را از «خط» بگیر، نه از «کادر»**: کادرِ کمی گشاد باید همان خط را بگوید،
  و خطی که فقط لبه‌اش ساییده شده نباید پاراگرافِ همسایه را بیاورد.
- **کادرِ روی سلول‌های خالی متنی ندارد** — نزدیک‌ترین **عنوانِ بالایش** را هم
  بفرست؛ همان است که ناحیه را نام‌گذاری می‌کند.
- **عنوان باید بالای کادر شروع شود، نه فقط «در یا بالای» آن.** با شرطِ سست، یک
  سلولِ داخلِ خودِ کادر به‌عنوان «عنوان» انتخاب می‌شد. این را مرورگر لو داد، نه تست.
- **تابعِ مختصات را تزریق‌پذیر کن**: jsdom چیدمان ندارد، پس تستی که
  `getClientRects` واقعی را صدا بزند سبز می‌شود بی‌آنکه چیزی ثابت کند.

## ⚠️ نکات حیاتی / Pitfalls

- **اول دادهٔ تحویلی را نگاه کن، بعد مدل را متهم کن.** «درکِ ضعیف» تشخیصی است که
  خیلی راحت پذیرفته می‌شود و تقریباً همیشه یک فیلدِ خرابِ بالادست دارد.
- **`closest()` برای «کدام ظرف» خوب است و برای «کجا داخلِ ظرف» فاجعه.** اگر
  ظرف بزرگ و یکپارچه است (بدنهٔ یک سند، بوم، نقشه)، فقط هندسه جواب می‌دهد.
- **`textContent` متنِ دیدنی نیست.** `<style>`, `<script>`, `<template>`,
  `aria-hidden` — همه داخلش می‌آیند.
- **fallbackِ «اگر چیزِ دقیق نبود، کلِ ظرف» تقریباً همیشه غلط است**؛ یک توصیفِ
  کوتاهِ درست از یک توصیفِ بلندِ بی‌ربط بهتر است.
- **قضاوت را با شواهد بکن، نه از روی متنِ گزارشِ عامل.** برنامه را بالا آوردم،
  کادرِ واقعیِ کاربر را از مختصاتِ ذخیره‌شده بازسازی کردم و روی صفحه کشیدم — و
  دیدم دورِ دوم **درست** انجام شده بود، برخلافِ انتظارِ همه.
- **چپ/راست را در RTL دوبار چک کن**، و همیشه یک نمونهٔ غیرمتقارن تست کن؛ نمونهٔ
  وسط، این باگ را پنهان می‌کند.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. برای هر فیلدی که به عاملِ خودکار می‌دهی بپرس «این می‌تواند با اطمینان غلط
   باشد؟» — اگر بله، یا درستش کن یا خالی بگذار.
2. «متنِ دیدنی» را با فهرستِ صریحِ تگ‌های نادیدنی بساز.
3. توصیف را از نزدیک‌ترین چیزِ خوانا بگیر، نه از کلِ ظرف.
4. گاردِ خروجی را طوری بگذار که **تصمیم** را مجبور به نوشته‌شدن کند، باریک و
   غیرقابلِ دستکاری توسطِ خودِ عامل.
5. ادعای عامل را با اجرای واقعیِ برنامه بسنج، نه با خواندنِ گزارشش.
