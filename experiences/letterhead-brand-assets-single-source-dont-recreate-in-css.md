# Letterhead assets: one visual ground truth — never re-create it per page

## 🎯 چالش / Challenge

فرمِ افرلتر سربرگ/پانوشتِ بانک را با CSS و متن «بازسازی» کرده بود و لوگویِ
کامپوزیتِ یک صفحهٔ دیگر (voucher) را قرض گرفته بود. نتیجه: رنگِ غلط (سرمه‌ای/
مشکی به‌جای آبیِ برند)، نامِ بانک دوبار (یک‌بار داخلِ عکسِ کامپوزیت، یک‌بار متنِ
کنارش)، و پانوشتِ سیاه‌وسفید — درحالی‌که همان لحظه، صفحهٔ نامهٔ رسمی assetهای
**عینیِ** استخراج‌شده از قالبِ Wordِ رسمی را داشت و درست چاپ می‌کرد. مالک با
عکسِ نامهٔ واقعی تفاوت را گزارش کرد.

## 💡 راه‌حل / Solution

- assetهای سربرگ (نشان+REGIONAL OFFICE، نامِ بانک+مجوز، بنرِ آدرس/SWIFT) فقط
  **یک‌جا** زندگی می‌کنند (`letter/letterhead.ts` — استخراجِ verbatim از قالبِ
  رسمی). هر صفحه/خروجی که سندِ رسمی می‌سازد (نامه، افرلتر، wordExport) همان‌ها
  را import می‌کند؛ هیچ صفحه‌ای حق ندارد سربرگ را با CSS/متن یا لوگویِ صفحهٔ
  دیگر شبیه‌سازی کند.
- بنرِ پانوشت خطِ بالایی‌اش را **داخلِ خودِ عکس** دارد ⇒ سطرِ جداکنندهٔ CSSی
  (border-top) را برای آن حالت خاموش کن وگرنه خطِ دوتایی می‌بینی.
- متنِ داخلِ عکس را به‌عنوانِ `alt` نگه دار (دسترس‌پذیری + جست‌وجوپذیری + ثابت
  ماندنِ constants متنی).
- تشخیصِ «کجاهای دیگر»: grep روی رشته‌های یکتا (SWIFT code، شماره تلفن،
  «REGIONAL OFFICE») همهٔ نقاطِ رندر را پیدا می‌کند؛ فرم‌های داخلی (credit-file/
  sanction) که در واقعیت سربرگِ نامه ندارند عمداً دست نخورند.

## ⚠️ نکات حیاتی / Pitfalls

- «شبیهِ» برند کافی نیست — مالک تفاوتِ رنگ/چیدمان را فوراً می‌بیند. اگر scan/
  استخراجِ عینی موجود است، همیشه همان را بکش؛ بازسازی فقط وقتی مجاز است که
  asset وجود نداشته باشد (و بعدش باید asset بشود، نه CSSِ محلی).
- لوگویِ «همان بانک» از صفحهٔ دیگر ≠ همان asset: نسخهٔ voucher کامپوزیتِ
  سرمه‌ای با متنِ داخلی بود؛ کنارِ متنِ صفحه، دوباره‌گویی می‌ساخت.
- عکسِ عنصرِ transform/zoom‌دار در Playwright ممکن است بریده بیفتد — برای
  تأییدِ بصری از کلِ صفحه اسکرین‌شات بگیر.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

- [ ] قبل از ساختنِ هر سربرگ/مهر/امضای رسمیِ جدید، `letter/letterhead.ts` (یا
  ماژولِ asset مشابه) را چک کن؛ اگر هست import کن، اگر نیست از سندِ رسمی
  استخراج و همان‌جا اضافه کن.
- [ ] بعد از هر تغییرِ برند، با grep روی رشته‌های یکتا همهٔ نقاطِ رندر را پیدا و
  یک‌جا به‌روز کن.
- [ ] با اسکرین‌شات کنارِ نمونهٔ واقعیِ مالک مقایسهٔ بصری کن — build سبز تفاوتِ
  رنگ/چیدمان را نمی‌گیرد.
