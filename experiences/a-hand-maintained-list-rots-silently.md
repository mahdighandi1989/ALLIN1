# فهرستِ دستی بی‌صدا می‌پوسد — قاعده را اجراشدنی کن

## 🎯 چالش / Challenge

بکاپِ سامانه، جدول‌ها را از یک **فهرستِ دستیِ ثابت** می‌خواند:

```python
def _targets():
    return {"customers": Customer, "facilities": Facility, ...}
```

روزی که نوشته شد، کامل بود. بعد از آن هر کسی جدولِ تازه‌ای اضافه کرد و این فهرست
را ندید. وقتی بالاخره شمرده شد: **۱۷ جدول از ۴۷ در بکاپ بودند.** نامه‌ها،
پیشنهادهای تسهیلات، بازبینی‌های اعتباری، نرخ ارز، تعرفه و کلِ پایگاه دانش بیرون
بودند.

یعنی بازیابی از بکاپ، مشتری‌ها را برمی‌گرداند و **هر سندی که کاربران ساخته بودند
بی‌صدا نبود** — بدونِ خطا، بدونِ هشدار، بدونِ هیچ ردی. فاجعه‌ای که فقط **روزِ
بازیابی** کشف می‌شود، یعنی بدترین روزِ ممکن.

هیچ‌کس خطا نکرده بود. صرفاً هیچ چیزی نپرسیده بود «جدولِ تازه‌ات را کجا گذاشتی؟»

## 💡 راه‌حل / Solution

> **هر جا فهرستی دستی باید با واقعیتِ سامانه هم‌گام بماند، آن هم‌گامی را به یک
> تستِ اجراشدنی تبدیل کن — با یک فهرستِ استثنای دلیل‌دار در کنارش.**

سه تکه، و هر سه لازم‌اند:

1. **فهرستِ پوشش** (`_targets()`) — چیزی که واقعاً هست.
2. **فهرستِ استثنا با دلیل** (`EXCLUDED = {table: "چرا نه"}`) — نه یک مجموعهٔ
   خالی از نام، بلکه **دلیلِ نوشته‌شده**. «لازم نیست» دلیل نیست.
3. **تستی که می‌گوید اتحادِ این دو باید همهٔ واقعیت را بپوشاند:**

```python
def test_every_table_is_covered_or_excluded_with_a_reason():
    unaccounted = set(Base.metadata.tables) - covered - set(EXCLUDED)
    assert not unaccounted, f"neither backed up nor excluded: {sorted(unaccounted)}"

def test_every_exclusion_gives_a_real_reason():
    for t, why in EXCLUDED.items():
        assert len(why.strip()) >= 20, f"'{t}' excluded without a usable reason"
```

حالا جدولِ تازه **همان‌جا که ساخته می‌شود** قرمز می‌شود و نویسنده‌اش مجبور است
یک تصمیم بگیرد. حافظه از مدار خارج می‌شود.

## 🧪 نمونه کد (Anonymized)

همان الگو برای هر رجیستریِ دستی:

```python
# مسیرها ↔ صفحه‌های مستندشده
unaccounted = {r.path for r in app.routes} - DOCUMENTED - set(UNDOCUMENTED_REASONS)
# فیلدهای مدل ↔ ستون‌های اکسپورت
unaccounted = set(Model.__table__.columns.keys()) - EXPORTED - set(SKIPPED_REASONS)
# کلیدهای ترجمه ↔ رشته‌های UI
unaccounted = used_keys - set(translations) - set(INTENTIONALLY_UNTRANSLATED)
```

## ⚠️ نکات حیاتی / Pitfalls

- **استثنا بدونِ دلیل، همان پوسیدگی است با ظاهرِ مرتب.** تستِ «دلیل واقعی باشد»
  را هم بنویس؛ در همین مورد دو تا از دلیل‌های خودم را رد کرد
  («may hold API keys» و «transient UI state» کوتاه‌تر از آن بودند که چیزی بگویند).
- **استثنایِ کهنه را هم بگیر:** اگر جدولی حذف شد ولی نامش در فهرستِ استثنا ماند،
  بی‌صدا حفره‌ای را که می‌پوشاند دوباره باز می‌کند. تستِ «استثناها باید موجود باشند».
- **دو جا نبودن:** چیزی نباید هم در پوشش باشد هم در استثنا.
- **«از قبل خراب بود» دلیلِ دست‌نزدن نیست** وقتی خرابی، از دست رفتنِ دادهٔ
  برگشت‌ناپذیر است. ولی تغییرِ مسیرِ بکاپ حساس است: افزودنی و برگشت‌پذیر انجامش
  بده و در سندِ تصمیم‌ها بنویس.
- **اعتبارنامه‌ها را رفلکسی داخل نکن.** «همه‌چیز را بکاپ بگیر» یعنی هشِ رمزها و
  کلیدهای API هم در یک فایلِ ابری. این یک تصمیمِ جداست — بگذارش در استثنا با
  همین دلیل و به مالک بگو.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. در پروژه دنبالِ هر `dict`/`list`ی بگرد که «همهٔ X»ها را دستی می‌شمارد.
2. بپرس: اگر فردا یک X تازه اضافه شود، **چه چیزی** می‌فهمد؟ اگر جواب «آدم» است،
   فهرست در حالِ پوسیدن است.
3. همین حالا اختلافش را با واقعیت بشمار — عدد معمولاً از انتظار بدتر است.
4. تستِ «پوشش ∪ استثنا = واقعیت» + تستِ کیفیتِ دلیل را اضافه کن.
5. شکافی که عمداً باز می‌ماند را در سندِ تصمیم‌ها بنویس، تا «یادم رفت» و
   «تصمیم گرفتم» شبیهِ هم نباشند.
