# فیلتر را درست کن، نه محلِ فراخوانی؛ و عددِ ثبت‌شده را به دستِ عامل برسان

دو ریشهٔ جدا، یک درسِ مشترک: **کاری که «انجام شده» به‌نظر می‌رسد، اگر آخرین حلقه
را نداشته باشد انجام نشده است.**

## 🎯 چالش الف — لایهٔ خودی که «صفحه» شمرده شد

یک ابزارِ گزارش‌گیری روی صفحه لایه می‌کشد (لایهٔ درگ، دیالوگِ ثبت، لایهٔ هایلایت).
هنگام عکس‌گرفتن باید بپرسد «زیرِ این نقطه چه چیزی از **صفحه** هست؟» و لایه‌های
خودش را رد کند:

```js
document.elementsFromPoint(x, y).filter((el) => !el.hasAttribute('data-our-layer'))
```

این فقط از **خودِ عنصر** می‌پرسد. صفتِ نشانه روی **ریشهٔ** دیالوگ است؛ کارتِ
سفیدِ داخلش صفت ندارد. و تصویربرداری **بعد از بازشدنِ دیالوگ** اجرا می‌شود — یعنی
`elementsFromPoint` یک `div` از داخلِ دیالوگ برمی‌گرداند، از آنجا نه ظرفِ صفحه
پیدا می‌شود نه بخشِ موردِ نظر، و منطقِ «فقط همین بخش را ببُر» بی‌صدا `null`
می‌شود و **کلِ سند** عکس گرفته می‌شود.

بدتر: دکمهٔ «دوباره عکس بگیر» که **داخلِ همان دیالوگ** است، ۱۰۰٪ مواقع خراب بود.

## 💡 راه‌حل الف

```ts
export function isOurOverlay(el?: Element | null) {
  return !!el?.closest?.('[data-our-layer]')     // عنصر **و اجدادش**
}
export function pageElementsAt(x: number, y: number, doc: Document = document) {
  return doc.elementsFromPoint(x, y).filter((el) => !isOurOverlay(el))
}
```

**در یک جا، نه در دو محلِ فراخوانی.** اگر همان‌جا که خراب بود وصله می‌زدم، لایهٔ
بعدی همان باگ را تکرار می‌کرد. یک تابع ⇒ هر چیزی که فردا به این لایه‌ها اضافه
شود هم پوشش دارد.

**تستش را با DOMِ تزریقی بنویس، چون jsdom `elementsFromPoint` ندارد** — پارامترِ
`doc` را برای همین بگذار:

```ts
pageElementsAt(10, 10, { elementsFromPoint: () => [dialogCard, sheetCell] } as any)
```

## 🎯 چالش ب — عددی که ثبت شد، ذخیره شد، و هرگز به دستِ عامل نرسید

کاربر دورِ یک ناحیه کادر می‌کشد و می‌نویسد «**در اینجا** این را بگذار». سامانه
مختصات را با دقت اندازه می‌گرفت، از جمله **کسرهای موقعیت داخلِ عنصرِ لنگر** —
تنها شکلی که با تغییرِ اندازهٔ پنجره هم معتبر می‌ماند.

عاملِ خودکار نتوانست «همان‌جا» بگذارد. علت **خواندنِ مدل نبود**: خلاصه‌ای که به
او می‌رسید آن کسرها را **اصلاً نداشت**. بدتر، دو مسیرِ خلاصه‌سازی وجود داشت
(دورهٔ عادی و صفِ فوری) و توصیفِ کامل فقط داخلِ یکی نوشته شده بود — همان که
استفاده نمی‌شد.

## 💡 راه‌حل ب

**۱) یک توصیف، همهٔ مسیرها.** `where_block(record)` را بیرون بکش و هر دو خلاصه
از آن استفاده کنند. تستی بگذار که **نسخهٔ دوم را ممنوع کند**:

```python
assert src.count("جای دقیق داخلِ همان گره") == 1
```

**۲) شکلِ قابلِ عمل را بفرست، نه فقط شکلِ خام.** «x=782 y=148» می‌گوید کادر در
پنجرهٔ ۱۳۵۲پیکسلیِ سه‌شنبه کجا بود. «از راستِ گره ۴۹٪، از بالای گره ۴۳٪» می‌گوید
**اینجا**.

**۳) بنویس با آن عدد چه باید کرد، و جوابِ غلط را به اسم بیاور.** عددی که کسی
مأمورِ عمل‌کردن به آن نیست، همان عددی است که رد می‌شود:

> جایش **همین** است — نه «بالای فرم»، نه «کنارِ نزدیک‌ترین دکمه». اگر ممکن نیست،
> بنویس کجا گذاشتی و **چرا نشد**، و نتیجه `partial` است نه `fixed`.

**۴) وقتی شاهد بی‌اعتبار است، عامل باید بگوید.** «اگر عکس کلِ سند را نشان می‌دهد
نه ناحیهٔ کادر، تصویربرداری خراب بوده — یافته بنویس، از روی عکسِ بی‌فایده حدس
نزن.» بدونِ این، عامل از یک شاهدِ خراب یک جوابِ مطمئن می‌سازد.

## ⚠️ نکات حیاتی / Pitfalls

- **`hasAttribute` در برابر `closest`**: هر جا «آیا این عنصر متعلق به X است؟»
  می‌پرسی، تقریباً همیشه سؤال دربارهٔ **زیردرخت** است، نه یک گره.
- **زمانِ اجرا را در نظر بگیر.** همان کد در دو لحظه دو جواب می‌دهد: قبل از
  بازشدنِ دیالوگ درست بود، بعدش غلط. بپرس «این تابع **کِی** اجرا می‌شود؟»
- **باگی که در هارنس بازتولید نشود، حل نشده است.** نسخهٔ اول در هارنسِ بدونِ
  دیالوگ سبز بود. هارنس را با **همان شرایطِ واقعی** بساز (دیالوگ باز، کادر در
  مرکزِ پنجره) و **کدِ قدیمی را هم اجرا کن** تا ببینی واقعاً قرمز می‌شود.
- **دو خلاصه = دو حقیقت.** هر جا یک واقعیت را دو بار توصیف می‌کنی، یکی عقب
  می‌ماند و معمولاً همان که استفاده می‌شود.
- **«ثبت کردم» یعنی «به دستش رسید»؟** زنجیره را تا آخر دنبال کن: اندازه‌گیری ⇒
  ذخیره ⇒ API ⇒ **خلاصه** ⇒ دستور ⇒ عمل. حلقهٔ گمشده معمولاً یکی‌مانده‌به‌آخر است.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. هر «مالِ ما یا مالِ آن‌ها؟» را با `closest` بپرس و در **یک** تابع بگذار.
2. باگ را در هارنسی با شرایطِ واقعی بازتولید کن و کدِ قدیمی را هم بسنج.
3. برای هر داده‌ای که ثبت می‌کنی بپرس «چه کسی قرار است به آن عمل کند و آیا
   می‌بیندش؟»
4. شکلِ **قابلِ عمل** را بفرست (کسر/نسبت)، نه فقط شکلِ خام (پیکسل).
5. جوابِ غلطِ رایج را در دستور به اسم بیاور.
6. توصیفِ مشترک را با تستِ «فقط یک نسخه» قفل کن.
