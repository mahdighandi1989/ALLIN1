# A DOM-to-image rasteriser is not the browser

## 🎯 چالش / Challenge

مالک گفت کادرِ نشان‌داده‌شده روی اسکرین‌شات «مختصاتش خیلی اشتباه و دقیق نیست»،
و از یک فرمِ چندصفحه‌ای «همهٔ صفحات» عکس گرفته می‌شود در حالی که فقط یک صفحه
لازم است.

هر دو به‌نظر مسئلهٔ **حساب مختصات** می‌آمدند. نبودند. `html-to-image` (و هر
ابزارِ هم‌خانواده) عنصر را **دوباره رندر می‌کند** داخلِ یک
`<svg><foreignObject>`: کلونِ عنصر را می‌سازد، computed style را رویش کپی
می‌کند، و نتیجه را رستر می‌کند. یعنی تصویرِ خروجی **همان چیزی نیست که مرورگر
روی صفحه کشیده** — و وقتی خودِ تصویر جابه‌جا باشد، هیچ ریاضیِ مختصاتی نجاتش
نمی‌دهد.

دو خرابیِ مشخص، هر دو در Chromium واقعی اندازه‌گیری شد:

1. **حاشیهٔ `auto` که به پیکسل حل شده، کپی می‌شود.** عنصرِ هدف `mx-auto` داشت؛
   در پنجرهٔ ۱۴۰۰px، computed margin برابرِ `36px` بود، پس کلون **۳۶ پیکسل به
   راست** داخلِ تصویرِ خودش کشیده شد. انحرافِ افقیِ ثابت ۳۶، عمودی صفر، مقیاس
   صفر. یعنی **هر علامت روی هر صفحه** همیشه ۳۶ پیکسل غلط بود.
2. **هرچه هدف عمیق‌تر، رندر بدتر.** «فقط همان صفحه را عکس بگیر» ⇒ دوربین را
   روی خودِ `.psheet` گرفتم. Chromium تیتر و پاراگراف را **کلاً ننوشت** و جدول
   را ۲۴۰px از لبهٔ راست بیرون انداخت؛ همان رستراییزر روی سطحِ والد، هر سه صفحه
   را بی‌عیب کشید. عنصرِ عمیق‌تر یعنی زمینهٔ چیدمانیِ بیشتری که از دست می‌رود.

## 💡 راه‌حل / Solution

**۱) `style: { margin: '0' }` به گزینه‌های رستر بده.** حاشیهٔ خودِ عنصر اصلاً
جایی در تصویرِ *همان* عنصر ندارد:

```ts
const data = await toJpeg(target, {
  quality: 0.82, pixelRatio: 1, backgroundColor: '#ffffff',
  style: { margin: '0' },          // بدون این، mx-auto تصویر را جابه‌جا می‌کند
})
```

**۲) دوربین را روی همان سطحی نگه دار که درست رندر می‌شود، و بعد تصویرِ آماده را
برش بزن.** برای «فقط یک صفحه از یک دستهٔ A4»:

```ts
const target = pickCaptureTarget(el)          // سطحِ کامل — وفادار رندر می‌شود
const sheet  = pickCropSheet(el, target)      // نزدیک‌ترین صفحه، یا null
// ... رستر کن، بعد:
const crop = sheetRect ? boxInImage(sheetRect, geom, image) : null
out = await annotate(data, box, crop)         // برش + علامت، در یک بوم
```

برش **بعد از** رستر، هم تصویرِ درست می‌دهد هم «فقط همان صفحه».

**۳) برشِ بیرونِ تصویر را clamp کن.** `drawImage` با ناحیهٔ بیرونی، حاشیهٔ
شفاف می‌کشد که روی JPEG **سیاه** درمی‌آید — همان باگِ «negativeِ تاریک» از راهِ
دیگر. ناحیهٔ خیلی کوچک یا برابرِ کلِ تصویر را کلاً بینداز دور.

**۴) دو مقیاس را قاطی نکن.** رستراییزر **border-box** (`offsetWidth/Height`) را
می‌کشد؛ `getBoundingClientRect` می‌تواند به‌خاطرِ `transform` فرق کند:

```
zoom = viewportBox / layoutBox      // فقط اثرِ CSS transform
scale = imagePixels / layoutBox     // چگالیِ رستر
```

و برای کانتینرِ اسکرول‌دار **هیچ اصلاحی لازم نیست**: border-box همان جعبهٔ
دیدنی است و رستراییزر همان را می‌کشد. (اولین بازنویسی‌ام این دو را یکی گرفت و
تستِ خودم آن را لو داد.)

## 🧪 نمونه کد (Anonymized)

هارنسی که **مسیرِ واقعی** را اجرا می‌کند (نه یک بازنویسیِ دستی): ماژول‌های
شیپ‌شده را با esbuild باندل کن، در یک صفحهٔ واقعی تزریق کن، و تصویرِ خروجی را
**پیکسل به پیکسل** با حقیقت مقایسه کن:

```js
// 1) همان تابع‌هایی که در production اجرا می‌شوند
esbuild.build({ entryPoints:['harness/entry.ts'], bundle:true, outfile:'harness/bundle.js' })

// 2) در مرورگرِ واقعی: بکش، عکس بگیر، و علامت را پیدا کن
const res = await page.evaluate((r) => window.shoot(r), drawnRect)
const amber = scanForOutline(res.data)                 // امتدادِ پیکسل‌های کهربایی
const truth = { x: cell.left - sheet.left, y: cell.top - sheet.top, ... }
expect(Math.abs(amber.x - truth.x)).toBeLessThan(4)    // ≤ ضخامتِ خودِ خط

// 3) و کنترل: اسکرین‌شاتِ خودِ مرورگر از همان عنصر
await page.locator('#p3').screenshot({ path: 'control.png' })
```

مقایسه با `control.png` همان چیزی بود که ثابت کرد **تصویر** خراب است نه ریاضی.

## ⚠️ نکات حیاتی / Pitfalls

- **تستِ واحدِ سبز اینجا هیچ چیزی ثابت نمی‌کند.** ۵۷ تستِ jsdom سبز بود در حالی
  که تصویرِ تولیدشده تیتر نداشت. jsdom نه چیدمان دارد نه `foreignObject`.
- **به تصویر نگاه کن، واقعاً.** انحرافِ ۳۶ پیکسلی و افتادنِ تیتر را فقط با
  بازکردنِ خروجی دیدم؛ هیچ assertی که نوشته بودم سراغش نمی‌رفت.
- **همیشه یک کنترل داشته باش** — اسکرین‌شاتِ خودِ مرورگر از همان عنصر. بدون آن
  نمی‌فهمی خطا از رستراییزر است یا از حسابِ تو.
- **RTL گیج‌کننده است**: انحرافِ +۳۶ در `dir="rtl"` شبیهِ «جدول بیرون زده»
  دیده می‌شود، نه «همه‌چیز ۳۶ رفته راست».
- **قاعدهٔ «عمیق‌تر = بدتر»** را به‌عنوان اصل نگه دار: اگر لازم شد ناحیهٔ
  کوچک‌تری عکس بگیری، **برش بزن**، دوربین را جابه‌جا نکن.
- `backgroundColor` برای JPEG اختیاری نیست (v154) — و برشِ بیرون‌زده همان
  پس‌زمینهٔ شفاف/سیاه را برمی‌گرداند.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. هر شکایت دربارهٔ «جای اشتباهِ علامت روی تصویر» را **اول** با مقایسهٔ تصویرِ
   رستر و اسکرین‌شاتِ مرورگر بررسی کن، نه با بازخوانیِ فرمول.
2. به رستراییزر `style:{margin:'0'}` بده.
3. کوچک‌ترین ناحیه را با **crop** بگیر، نه با هدف‌گیریِ عنصرِ عمیق.
4. برش را clamp کن (داخلِ تصویر، حداقلِ اندازه، و «کلِ تصویر ⇒ بی‌برش»).
5. صحت را با یک هارنسِ مرورگرِ واقعی که **کدِ شیپ‌شده** را باندل می‌کند بسنج،
   و اختلاف را برحسبِ پیکسل گزارش کن.
