# دو واقعیتِ مستقل، دو شاخهٔ مستقل — `elif` قاتلِ خاموش است

## 🎯 چالش / Challenge

وقتی کاربر زیرِ یک کارِ «انجام‌شده» دوباره می‌نوشت، دو چیز باید اتفاق می‌افتاد:

1. اگر آن کار را قبلاً «فوری» کرده بود، برگردد به صفِ فوری.
2. وضعیتش از «پاسخ داده شد» برگردد به «باز».

کد این بود:

```python
elif r.urgent_done_at is not None:
    r.urgent_done_at = None
elif r.status == ANSWERED:
    r.status = OPEN
```

هر کدام جداگانه درست کار می‌کردند. ولی رکوردی که **هر دو شرط** را داشت — و
این دقیقاً پرتکرارترین حالتِ واقعی بود، چون کاربر همان چیزی را پیگیری می‌کند که
برایش عجله داشته — وارد شاخهٔ اول می‌شد و **هرگز به دوم نمی‌رسید**.

نتیجه: وضعیت روی «پاسخ داده شد» می‌ماند و رنگِ سبزِ «درست شد» را نگه می‌داشت،
در حالی که کاربر داشت می‌گفت هنوز درست نشده. **هیچ خطایی، هیچ لاگی، هیچ
استثنایی.** فقط یک رنگِ دروغ.

## 💡 راه‌حل / Solution

> **`elif` یعنی «این شرط‌ها یک انتخابِ واحدند». اگر شرط‌ها دربارهٔ چیزهای
> متفاوتی‌اند، `elif` یک ادعای غلط است — و ادعای غلط بی‌صدا شکست می‌خورد.**

```python
if r.urgent_done_at is not None:      # درباره‌ی صف
    r.urgent_done_at = None
if r.status in (ANSWERED, APPROVED):  # درباره‌ی وضعیت
    r.status = OPEN
```

معیارِ ساده: **موضوعِ شرط‌ها را بخوان.** اگر دو شرط دربارهٔ دو *صفتِ متفاوتِ*
یک شیءاند، نباید در یک زنجیره باشند. زنجیره فقط وقتی درست است که شرط‌ها حالت‌های
جایگزینِ **یک** صفت باشند (`if kind == 'a' ... elif kind == 'b'`).

## 🧪 نمونه کد (Anonymized)

تستی که این را می‌گیرد باید **هم‌زمانیِ** دو شرط را بسازد — نه هر کدام را جدا:

```python
async def test_it_reopens_even_when_it_had_been_rushed(...):
    sheet = await make_sheet()
    await rush(sheet)          # شرطِ ۱
    await answer(sheet)        # شرطِ ۲
    await owner_note(sheet)    # ← حالا هر دو برقرارند
    assert sheet.status == "open"      # با elif اینجا «answered» بود
    assert sheet.glow.tone == "open"
```

تستِ «فقط پاسخ‌داده‌شده» و تستِ «فقط فوری» هر دو **سبز** بودند. فقط ترکیب قرمز شد.

## ⚠️ نکات حیاتی / Pitfalls

- **پرتکرارترین حالتِ واقعی معمولاً همان ترکیب است.** کاربر همان چیزی را پیگیری
  می‌کند که برایش عجله داشته؛ پس مسیرِ خراب، مسیرِ اصلی بود نه لبه‌ی نادر.
- **پوششِ تست فریب می‌دهد.** هر دو شاخه اجرا شده بودند؛ چیزی که اجرا نشده بود
  ترکیبشان بود. برای هر زنجیرهٔ شرطی بپرس: «اگر هر دو درست باشند چه؟»
- **خروجیِ این باگ یک رنگ بود، نه یک خطا.** هر جا وضعیت به رنگ/برچسب ترجمه
  می‌شود، غلط‌بودنش هیچ ردی نمی‌گذارد — کاربر باید بگوید.
- **موقعِ اضافه‌کردنِ شرطِ تازه به یک `elif` موجود، کلِ زنجیره را دوباره بخوان.**
  این باگ وقتی ساخته شد که شاخهٔ «صفِ فوری» به زنجیره‌ای اضافه شد که از قبل
  دربارهٔ «وضعیت» بود.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. هر `elif` را پیدا کن و بپرس: شرط‌ها دربارهٔ **یک** صفت‌اند یا چند تا؟
2. اگر چند تا: به `if`های مستقل بشکن.
3. برای هر زنجیره‌ای که نگه می‌داری، یک تست با **همهٔ شرط‌ها هم‌زمان** بنویس.
4. باگ را با برگرداندنِ کدِ قدیمی بیازما — اگر تستِ تازه قرمز نشد، چیزی را که
   فکر می‌کنی نمی‌سنجد.
