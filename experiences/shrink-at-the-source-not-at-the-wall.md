# کوچک‌کردن در منبع، نه بالابردنِ دیوار

## 🎯 چالش / Challenge

کاربر اسکرین‌شاتِ خودش را می‌چسباند و ثبت رد می‌شود:

```
shot: String should have at most 1400000 characters
```

~۱٫۴ مگابایت base64 — **کوچک‌تر از یک PNGِ معمولیِ تمام‌صفحه**. یعنی تنها چیزی که
این قابلیت را ارزشمند می‌کند (عکسِ واقعیِ آنچه کاربر دیده) همان چیزی بود که رد
می‌شد. و پیام انگلیسی بود، دربارهٔ نامِ فیلدی که کاربر نمی‌شناسد، بدونِ اینکه
بگوید چه کند.

## 💡 راه‌حل / Solution

**۱) بالابردنِ عدد، راه‌حل نیست — فقط دیوار را جابه‌جا می‌کند.** ریشه این است که
صفحه **هر چیزی را که کلیپ‌بورد داشت** می‌فرستاد. یک اسکرین‌شاتِ 4K حدود ۱۰–۱۵
مگابایت است و **هیچ‌کدام از آن حجم، شاهد نیست**: عکس را یک انسان می‌بیند و یک مدلِ
متنی توصیفش می‌کند؛ بالاتر از دو-سه هزار پیکسلِ ضلعِ بلند معنا اضافه نمی‌شود.

```ts
// ضلعِ بلند را سقف بزن، بعد کیفیت را پله‌پله پایین بیاور، بعد ابعاد را نصف کن
let size = planSize(w, h, MAX_PX)
for (const q of [0.85, 0.7, 0.55, 0.42]) {
  const out = canvas.toDataURL('image/jpeg', q)
  if (out.length <= MAX_CHARS) return out
}
```

**۲) این مسیر هرگز نباید شکست بخورد.** اگر مرورگر canvas ندهد یا تصویر دیکد نشود،
**اصلِ تصویر** را برگردان. عکسِ بزرگ از بی‌عکسی بهتر است.

**۳) سقفِ سرور را حذف نکن — فاصله بگذار.** تصویر داخلِ بدنهٔ JSON می‌آید و در
حافظه باز می‌شود؛ بدونِ هیچ سقفی یک درخواست سرور را می‌خواباند. سقف را چند برابرِ
چیزی بگذار که صفحه می‌فرستد، و این فاصله را **تست کن**:

```python
assert MAX_SHOT_BYTES >= CLIENT_TARGET * 2   # دو طرف نباید با هم مسابقه بدهند
```

**۴) «خیلی بزرگ» و «اصلاً تصویر نیست» دو چیزند.** کدِ ما برای هر دو `None`
برمی‌گرداند، پس عکسی که از اعتبارسنجی رد می‌شد **بی‌صدا دور انداخته می‌شد**:
رکورد بدونِ عکس ثبت می‌شد و کسی خبردار نمی‌شد. «چیزی برای ذخیره نبود» سکوت است؛
«چیزی فرستادی و دور انداختیم» باید خطا باشد.

**۵) پیام را به زبانِ کاربر و با دستورِ عمل بنویس**، نه با نامِ فیلد و شمارهٔ بایت.

## ⚠️ نکات حیاتی / Pitfalls

- **PNGِ شفاف که بدونِ زمینه به JPEG برود سیاه درمی‌آید.** اول بوم را سفید پر کن.
- **`loadImage` بدونِ مهلت می‌تواند تا ابد منتظر بماند** — اگر مرورگر نه `onload`
  بدهد نه `onerror` (دقیقاً رفتارِ jsdom با data URL)، دیالوگ بدونِ عکس و بدونِ
  خطا می‌ماند. این را **تست پیدا کرد**، نه بازبینیِ کد.
- **تستِ حجم را با دادهٔ واقعاً فشرده‌نشدنی بزن.** اولین نمونهٔ من راه‌راه بود و
  ۵۵ مگابایت به ۰٫۳ مگابایت فشرده شد — یعنی اصلاً مسیرِ موردِ نظر را اجرا نکرد.
  نویزِ تصادفی تنها چیزی است که مثلِ یک اسکرین‌شاتِ واقعیِ پر از متن رفتار می‌کند.
- **تستِ «قبول شد» کافی نیست**؛ یک تست هم بگذار که عکس **واقعاً ذخیره و سرو** شده
  باشد، وگرنه درخواستی که بایت‌ها را گم می‌کند از همهٔ تست‌ها رد می‌شود.
- **بخشِ محاسباتی را خالص و تست‌پذیر نگه دار** (نسبت، اندازه، شرط‌ها) و بخشِ
  canvas را نازک؛ jsdom بوم ندارد و تستی که آن را mock کند، mock را تست می‌کند.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. وقتی کاربر به سقفِ اندازه می‌خورد، اول بپرس «چرا اصلاً این‌قدر بزرگ است؟»
2. در **منبع** کوچکش کن، با مسیرِ fallback که هرگز داده را گم نمی‌کند.
3. سقفِ سرور را نگه دار ولی با فاصلهٔ آزموده‌شده از هدفِ کلاینت.
4. هر «رد کردن»ی را از «چیزی نبود» جدا کن؛ دورانداختنِ بی‌صدا بدترین حالت است.
5. پیام را به زبانِ کاربر و با دستورِ عمل بنویس.
6. انتها به انتها در مرورگر واقعی، با دادهٔ واقعاً سنگین، امتحان کن.
