# ابزارِ پایش باید «نسنجیدم» را از «صفر» جدا کند

## 🎯 چالش / Challenge

یک ناظرِ خودکار هر هفته سطحِ سامانه را می‌شمارد (صفحه، دکمه، endpoint) و قاعده‌اش
این است: **کاهشِ هر عدد یعنی قابلیتی حذف شده — هشدارِ بلند بده.** ابزار روی یک
محیطِ تازه اجرا شد که وابستگی‌هایش نصب نبود، و دو جور دروغ گفت:

1. شمارندهٔ endpointها، برنامه را در یک subprocess import می‌کرد و
   `except Exception: return []` داشت. خروجی شد **`routes: 0`** (هفتهٔ قبل: ۲۱۳).
   یعنی ناظر آمادهٔ اعلامِ «۲۱۳ endpoint حذف شد» بود، در حالی که فقط یک کتابخانه
   نصب نبود. **بلندترین هشدارِ ممکن، از یک مشکلِ محیطی.**
2. اسکریپتِ اجرا هر قدم را چنین صدا می‌زد: `cmd 2>&1 | tail -3`. کدِ خروجیِ یک
   لوله، کدِ **آخرین** فرمان است — و `tail` همیشه صفر برمی‌گردد. پس یک تستِ
   کاملاً اجرانشده («ماژول پیدا نشد») با `exit=0` بایگانی شد: **ابزاری که کارش
   گرفتنِ قرمز است، قرمز را سبز ثبت می‌کرد.**

هر دو یک ریشه دارند: **مسیرِ شکست، شبیهِ یک نتیجهٔ معتبر بسته‌بندی شده بود.**

## 💡 راه‌حل / Solution

1. **«اندازه‌گیری نشد» یک مقدارِ جداست، نه صفر.** استثنای اختصاصی پرت کن
   (`MeasurementFailed`)، و در خروجیِ ساختاریافته `null` بگذار — نه `0`، نه `[]`.
2. **دلیل را همراهِ خطا حمل کن** (`stderr` واقعی)، وگرنه خوانندهٔ بعدی از صفر
   تشخیص می‌دهد.
3. **گزارشِ انسانی باید «⚠️ اندازه‌گیری نشد» بنویسد**، نه یک عدد. جدولی که
   جایِ خالی‌اش شبیهِ داده است، بدتر از جدولِ خالی است.
4. **خروجِ غیرصفر** وقتی چیزی سنجیده نشد، تا صداکننده هم بفهمد.
5. **هر لولهٔ شل `set -o pipefail` می‌خواهد.** لوله‌زدن به `tail` درست است (خروجیِ
   کامل به‌دردنخور است)؛ چیزی که غلط است، نداشتنِ `pipefail` است.
6. **preflight**: پیش از هر سنجش، وجودِ ابزارها/وابستگی‌ها را چک کن و بلند بگو.
   ناظری که محیطِ نیم‌بند را می‌سنجد، **محیط** را گزارش می‌دهد نه محصول را.
7. **هشدارِ الکی را قبل از تولدش بکش:** هر قاعدهٔ تازه را روی دادهٔ واقعی
   بیازما. قاعدهٔ «پیوستِ یتیم» اول همهٔ پیوست‌های بی‌حساب را یتیم می‌شمرد، در
   حالی که یک دستهٔ بزرگشان از راهِ دیگری کاملاً قابلِ‌دسترس بودند.

## 🧪 نمونه کد (Anonymized)

```python
class MeasurementFailed(RuntimeError):
    """شمارش انجام نشد — با «شمارش شد و صفر بود» یکی نیست."""

def count_endpoints() -> list[dict]:
    r = subprocess.run([sys.executable, "-c", PROBE], capture_output=True, text=True)
    line = next((l for l in r.stdout.splitlines() if l.startswith("@@")), "")
    if not line:                                  # ❌ قبلاً: return []
        raise MeasurementFailed(
            f"probe produced nothing (exit={r.returncode}): {r.stderr.strip()[-200:]}")
    return json.loads(line[2:])

def build() -> dict:
    errors = []
    try:
        routes = count_endpoints()
    except MeasurementFailed as e:
        routes, _ = None, errors.append(f"routes: {e}")   # None ≠ 0
    return {"routes": routes,
            "totals": {"routes": len(routes) if routes is not None else None},
            "errors": errors}
```

```bash
step "tests" 1800 bash -c "cd app && pytest -q 2>&1 | tail -3"

PF='set -o pipefail;'
step "tests" 1800 bash -c "$PF cd app && pytest -q 2>&1 | tail -3"
```

## ⚠️ نکات حیاتی / Pitfalls

- **`except Exception: return <مقدارِ خالی>`** در کدِ پایش، همیشه اشتباه است.
  در کدِ محصول ممکن است fallbackِ درستی باشد؛ در کدِ **سنجش** هرگز.
- **صفرِ واقعی را هم نکش:** اگر برنامه‌ای واقعاً هیچ endpointی ندارد، باید `0`
  گزارش شود. تستِ «صفرِ واقعی صفر می‌ماند» را هم بنویس، وگرنه پاندول برعکس
  می‌چرخد و یک نقصِ واقعی پنهان می‌شود.
- **پیامِ کنسولِ مرورگر برای پاسخِ بد، URL ندارد**
  («Failed to load resource: … 404»). رویدادِ **response** را ثبت کن. یافته‌ای
  که نمی‌شود مکانش را پیدا کرد، نصفِ یافته است — و یک هفته بی‌اقدام می‌ماند.
- **بازآزماییِ یک مورد نباید هزینهٔ کلِ جاروب را داشته باشد.** یک آرگومانِ
  ساده برای محدودکردنِ دامنه بگذار، وگرنه بعد از هر اصلاح وسوسه می‌شوی
  «احتمالاً درست شد» بنویسی به‌جای اینکه بسنجی.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

برای هر اسکریپتِ پایش/بازرسی/CI این‌ها را چک کن:

1. هر `except` که مقدار برمی‌گرداند — آیا «خطا» را شبیهِ «نتیجه» می‌کند؟
2. هر لوله در شل — `pipefail` دارد؟ (`cmd | tee`, `cmd | head`, `cmd | jq` همه.)
3. خروجیِ ساختاریافته — برای «نسنجیدم» یک مقدارِ متمایز دارد؟
4. گزارشِ انسانی — تفاوتِ صفر و نسنجیده را **نشان** می‌دهد؟
5. کدِ خروجی — وقتی چیزی سنجیده نشد، غیرصفر است؟
6. پیش از سنجش، وجودِ پیش‌نیازها اعلام می‌شود؟
7. هر قاعدهٔ هشدار — روی دادهٔ واقعی آزموده شده که الکی شلیک نکند؟
8. می‌شود فقط یک مورد را دوباره سنجید، یا باید کلِ اجرا تکرار شود؟
