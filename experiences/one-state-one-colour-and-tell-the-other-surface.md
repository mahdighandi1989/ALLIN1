# One state, one colour — and tell the other surface

## 🎯 چالش / Challenge

یک گردش‌کارِ چهارحالته (منتظرِ ناظر → پاسخ داده شد → تأییدِ مالک → بایگانی) در دو
جا رنگ می‌شد: **نشانِ کوچک** روی تختهٔ فهرست، و **هایلایتِ** کشیده‌شده روی خودِ
صفحه. مالک گزارش داد رنگ‌ها آن چیزی نیست که باید. سه خرابیِ جدا پیدا شد و هیچ‌کدام
را تستِ موجود نمی‌گرفت:

1. **دو پالت که فقط با خودشان سازگار بودند.** نشان `answered=سبز، approved=آبی`
   داشت؛ هایلایت دقیقاً **برعکس**. هر ماژول تستِ خودش را داشت و سبز بود، چون هر
   تست همان نقشهٔ رنگِ کنارِ خودش را می‌خواند. چیزی که غلط بود **نسبت** بود، و
   نسبت صاحبِ تست نداشت.
2. **رنگ سؤالِ اشتباهی را جواب می‌داد.** رنگِ هایلایت از «نتیجه» ساخته می‌شد
   (انجام شد / ناقص / نشد / با مالک)، نه از «نوبتِ کیست». پس برگه‌ای که جوابش
   آمده بود می‌توانست هنوز نارنجی بماند. تصمیمِ اولیه دلیلِ درستی داشت
   («دیوارِ سبزِ بی‌معنا بدتر از بی‌رنگی است») ولی آن دلیل دربارهٔ **کلمه** بود،
   نه دربارهٔ **رنگ**.
3. **یک سطح حالت را عوض می‌کرد و به سطحِ دیگر نمی‌گفت.** تخته بعد از هر کنش
   `load()` خودش را صدا می‌زد؛ لایهٔ هایلایت روی صفحهٔ دیگر فقط با یک رویداد
   (یا focus/ناوبری) دوباره می‌خواند. پس رنگِ روی صفحه تا وقتی تب focus نمی‌گرفت
   عوض نمی‌شد — و کاربر می‌گفت «عوض نشد»، که درست بود.

## 💡 راه‌حل / Solution

**۱) رنگ = وضعیتِ چرخه. کلمه = جزئیات.** یک بُعد برای رنگ انتخاب کن و همان یکی.
جزئیاتِ ریزتر (نتیجه، کیفیت، شواهد) در **نشان و tooltip** می‌نشیند، جایی که جا
برای کلمه هست. رنگ ظرفیتِ یک سؤال را دارد، نه دو تا.

```ts
// وضعیت رنگ می‌دهد؛ tone‌ی «نتیجه» فقط برای وضعیتِ ناشناخته می‌ماند
export const toneOf = (r: Sheet): string =>
  LIFECYCLE[r.status] || TONE_COLOR[r.glow?.tone || ''] || TONE_COLOR.open
```

tone‌های قدیمی را **پاک نکن** — نگهشان دار (قانونِ «قابلیت را حذف نکن»)؛ فقط
دیگر هایلایت را رنگ نکنند.

**۲) دو پالت را به هم بسنج، نه هرکدام را به خودش.** تست باید از یک ماژول به
ماژولِ دیگر بپرد؛ وگرنه هر دو با خودشان سازگار می‌مانند و با هم نه:

```ts
const TAILWIND = { 'bg-emerald-600': '16, 185, 129', 'bg-blue-600': '59, 130, 246', … }
it.each(['open','answered','approved','filed'])('agrees on «%s»', (s) => {
  expect(TONE_COLOR[s]).toBe(TAILWIND[TONE[s]])      // نشان ↔ هایلایت
})
```

**۳) اعلام را در گلوگاه بگذار، نه در تک‌تکِ کنش‌ها.** همهٔ کنش‌ها (تأیید، حذف،
یادداشت، پیوست) به یک `load()` ختم می‌شوند — اعلام همان‌جا برود، تا **کنشِ بعدی**
که کسی اضافه می‌کند هم خودبه‌خود پوشش داشته باشد:

```ts
const load = useCallback(async () => {
  const d = await api.list(…)
  setRows(d.rows)
  notifySheetsChanged()      // ← لایهٔ دیگر می‌شنود
}, [filter])
```

و قراردادش را با **اسکنِ سورس** ببند، چون همین یک خط است که فراموش می‌شود:

```ts
const load = SRC.slice(SRC.indexOf('const load = useCallback'), SRC.indexOf('void load()'))
expect(load).toContain('notifySheetsChanged()')
for (const fn of ['const approve =', 'const remove =', 'const addNote ='])
  expect(SRC.slice(SRC.indexOf(fn), SRC.indexOf(fn) + 700)).toContain('load()')
```

دو نیمهٔ قرارداد **با هم** سنجیده می‌شوند: اگر کنشی `load()` را رها کند، اعلام
هم برایش اجرا نمی‌شود.

## ⚠️ نکات حیاتی / Pitfalls

- **«همهٔ تست‌ها سبزند» دربارهٔ قراردادِ بین‌ماژولی چیزی نمی‌گوید.** اگر دو جا یک
  حقیقت را جدا کدگذاری می‌کنند، تستشان هم باید بین‌ماژولی باشد.
- **جهشی امتحان کن.** دو رنگ را جابه‌جا کن و خطِ اعلام را بردار؛ اگر تست قرمز
  نشد، تست وجود ندارد.
- **یک تصمیمِ قدیمیِ درست می‌تواند جوابِ سؤالِ اشتباه باشد.** «سبز فقط با مدرک»
  قاعدهٔ خوبی برای **ادعا** بود، نه برای **رنگِ نوبت**. وقتی مالک قاعدهٔ صریح
  می‌دهد، قاعدهٔ قبلی را به جایِ درستش منتقل کن، نه اینکه دور بیندازی یا نگه داری.
- **هر مصرف‌کنندهٔ حالت را فهرست کن.** هر جا حالت را می‌خواند باید یا refetch کند
  یا خبر بگیرد؛ «فقط در ناوبری تازه می‌شود» یعنی کاربر چیزِ کهنه می‌بیند و حق
  دارد بگوید کار نمی‌کند.
- **گردشِ کاری که «هر دور» انجام می‌شود باید در همهٔ دورها باشد** — دورِ سریع هم
  یک دور است. وگرنه کارِ بسته‌شده تا دورِ کامل روی صفحه می‌ماند.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere

1. یک بُعد برای رنگ انتخاب کن و بنویس چرا؛ بقیه می‌شوند کلمه.
2. هر جا همان حالت را رنگ/برچسب می‌زند پیدا کن و **به هم** بسنج.
3. اعلامِ تغییر را در گلوگاهِ مشترک بگذار، نه در هر کنش.
4. قرارداد را با اسکنِ سورس قفل کن، و جهشی تأییدش کن.
5. هر گامِ «در هر دور» را در **همهٔ** روتین‌ها بگذار، نه فقط کاملش.
